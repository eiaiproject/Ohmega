# Antislop audit 001, 2026-09-14

Scope: landing page `src/pages/index.astro` plus header, footer, mobile menu, product cards, blog teaser/cards, blog index, 404, BaseLayout, Button, WhatsAppButton, Icon, SectionHeading, theme tokens in `src/assets/styles/global.css`. Copy is Indonesian, so the English-pattern rules (R-02, R-15, R-16) were checked by meaning, not literal strings.

Mode: AFTER. Nothing was modified. Numbers not mentioned are not touched.

## Findings

### HIGH

1. R-24/R-26, nav links go nowhere and one is a dead anchor: `src/data/navigation.ts` has `Tentang -> /#tentang` but no `id="tentang"` section matches that intent; `ProducerSection.astro:6` and `Footer.astro:7` both use `id="tentang"`, so the nav resolves to the footer, not an About block. `CertificationsSection.astro:9` also has `id="sertifikasi"` with no nav entry. Fix: give the producer section the `tentang` anchor, remove `id="tentang"` from the footer, and either add Sertifikasi to nav or keep it out of nav deliberately.
2. R-27, card grids have no empty/error UI: `ProductsSection.astro:20-22`, `BlogTeaserSection.astro:12-34`, `src/pages/blog/index.astro:23-37`, and `ArticleCard.astro` handle only the populated state. Fix: keep the blog index empty message, add an explicit empty and error presentation for the products grid and article cards, since these are the data-displaying UI.
3. R-25, WhatsApp button text fails contrast: white `#FFFFFF` on `--color-whatsapp` `#25D366` is 1.98:1 and on the hover `#1FBA59` is 2.55:1, below the 4.5:1 normal-text floor. Affects `Button.astro` `whatsapp` variant, `WhatsAppButton.astro`, product cards, delivery, hero, header, sticky CTA. Fix: dark text `#173F2C` on the WhatsApp green (5.94:1, hover 4.61:1).
4. R-25, muted text on the coming-soon product overlay fails: `text-muted` `#607067` over the `bg-soft-green-soft/60` overlay blend (`#DBE4DE`) is about 4.03:1, below 4.5:1. In `ProductCard.astro:21-27`. Fix: use `text-text` `#183126` for the "Segera Hadir" pill.
5. R-35, delivered without a recorded run: `npm run build` here fails with `astro: command not found` (dependencies not installed), so there is no build or click-through evidence. Fix: run `npm install`, then `npm run build`, then click every CTA, nav link, mobile menu, map iframe, cert links, and both CTAs on 404 with an empty-console check.

### MEDIUM

6. R-01, no gradients or glows present, but the reason is unwritten. Palette is flat brand greens plus yolk. Fix: one line in the report or a design note, e.g. flat color carries hierarchy, no gradient or glow needed. No visual change.
7. R-04, icons are a thin-stroke outline set and repeat the same glyph: `nutrition` for all three nutrition cards (`NutritionSection.astro:16-28`, `nutrition.ts:12-16`) and `check` on hero list, product badges, and trust bar. Fix: keep the outline set as a deliberate brand choice, give each nutrition card a distinct relevant icon, and keep `check` only where it means done/verified.
8. R-06, uppercase eyebrow labels appear in every section with wide tracking (`HeroSection.astro:13`, `ProductsSection.astro:11`, `SectionHeading.astro:7`, `FinalCTASection`, blog header, 404) with no written typeface reason. Fix: one line stating Nunito Sans ExtraBold uppercase eyebrows are the section-voice motif. No visual change unless the motif is reworked.
9. R-14, three identical 3-column card grids in a row: products (`ProductsSection.astro:20`), nutrition (`NutritionSection.astro:16`), order steps (`OrderStepsSection.astro:21-31`), each with identical radius, border, shadow, and hover. Only nutrition has a weak featured variant. Fix: differentiate by content, e.g. nutrition values as the hierarchy with one featured card, products as commerce cards, steps as numbered process rows.
10. R-09, two capsule badges without a written functional need: `Pilihan Keluarga` and `Paling Hemat` (`products.ts:44,58`, `ProductCard.astro:15-20`). Fix: write the one-line need (real merchandising status, savings computed from `prices.yaml`) or remove them.
11. R-19, motion has no written UX purpose: global `.reveal` fade-up, hero entrance, badge pop, card hover lift, article image zoom. `prefers-reduced-motion` is handled in `global.css:68-71`. Fix: one line per motion pattern, e.g. reveal guides scroll order, card lift signals tappability; drop motion that has no job.
12. R-08, arrows on every secondary CTA by default (`HeroSection.astro:25`, `BlogTeaserSection.astro:23`, `404.astro:13`, `ArticleCard.astro:52-58`) with no written purpose. Fix: keep arrows only where they signal forward movement and state that rule in one line.
13. R-10/R-12/R-13, no glassmorphism, soft selective shadows (`--shadow-card`, `--shadow-soft`), no glow. Header uses `backdrop-blur` over `bg-cream/90` only (`Header.astro:9`). Fix: no change, record that blur is limited to the sticky header for legibility.
14. R-07/R-22, no background grid or generic illustrations; visuals are real product photos and certification logos. Fix: no change, record real-photo direction.

### LOW

15. No bento, terminal, 3-step, logo bar, or pricing-table template. 19. R-31, no decision reasons are written down anywhere. Fix: add the one-line reasons from items 6, 7, 8, 10, 11, 12 above to the design note or report so Purpose-Gate has evidence.
